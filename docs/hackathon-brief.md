## Sprint playbook (from the guidebook)

- Read the complete statement carefully: identify the user, core problem, expected output, constraints, and how success is demonstrated.
- Choose a narrow, testable solution; sketch architecture and main prompt flow before optional features.
- Build the core path first — one end-to-end user journey. Don't spend early hours polishing while the essential workflow is incomplete.
- Test deliberately: normal inputs, ambiguous inputs, invalid inputs, relevant edge cases. Fix what breaks the main task.
- Deploy early so there's time to resolve configuration, access, and runtime issues.
- Write the abstract and deck from the actual implementation — never claim safeguards or features that aren't present.
- Submit with a buffer; no late grace period.
